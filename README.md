# Nova

**SG Intelligence Tech LLC**

Nova is a growing AI system designed to develop around a purpose.

Nova is a working, self-governed autonomy system. It remembers, plans, uses tools, manages ongoing work, checks its own results, and improves how it operates. Its intelligence comes from all of its parts working together, not from one model doing everything. Nova can grow into new kinds of work while continuing to govern itself. A mission gives Nova somewhere to aim.

## What Nova Is

Most software waits for a person to open it, give it a command, and guide every step. Nova can receive direct requests, but its work does not end when a conversation ends. It has an active runtime, persistent memory, ongoing work, recurring maintenance, and a record of what it has seen and done. It can carry unfinished work forward, notice when something changes, and return to problems that still need attention.

Self-governed means Nova does more than produce an answer. It keeps track of its own condition and the condition of the work moving through it. It can decide whether it has enough information to act, choose from the tools available to it, record the evidence produced by those tools, and compare the outcome with what was expected. When work cannot move forward, Nova can preserve the reason instead of quietly erasing the problem or pretending it was completed.

Nova is also larger than the AI models it uses. A language model may help Nova understand a request, consider choices, or form a response, but the model is one part of the system. Nova owns the memory, tools, policies, work records, evidence, testing, runtime supervision, and feedback that turn intelligence into dependable action. Models can be changed or selected to suit the computer Nova is running on without replacing Nova itself.

This is why Nova should be understood as an autonomy system rather than a single assistant program. It brings many forms of intelligence and action into one continuing process.

## How Nova Works

Nova begins with intent. It listens for what a person is asking, what the current situation requires, or what its own systems have discovered. It then works out what kind of response or action fits that intent. Some requests can be answered directly. Others need memory, research, files, vision, a data source, a system check, or a longer chain of work.

When the work is larger than one action, Nova can organize it into Work Trees. A Work Tree keeps the goal, branches, tasks, dependencies, blockers, tool choices, and evidence together. This gives Nova a way to continue meaningful work over time without reducing everything to a stream of disconnected prompts. It also gives a person a way to see what Nova believes is open, complete, blocked, or ready to move.

Nova has memory for continuity and learning. It can retain useful facts, identity information, corrections, and relevant context. Memory is not treated as an unlimited pile of old conversation. Nova has rules for when information should be remembered, when it should be recalled, and when stale or contaminated material should be removed. This allows memory to support judgment without silently becoming the source of false certainty.

Nova also has tools that let decisions become real work. Those tools include local file access, system inspection, research, web access, vision, voice, patching, data pipelines, and domain-specific capabilities. Tool use is recorded. Nova can distinguish between a tool being available, a tool being allowed, and a tool actually returning valid evidence. That distinction matters because an attempted action is not the same as a successful result.

Through Leah, the web interface, the command line, voice, and other front doors, people can interact with the same underlying Nova. These surfaces are different ways into the system, not separate versions of its intelligence.

## Honesty Is Part of the Work

Nova is built around a simple but demanding idea: its view of itself should come from evidence.

If a test has not run, Nova should not treat it as passed. If a result is old, Nova should not present it as current. If a task is blocked, the blocker should remain visible. If one part of the system owns a fact, another part should not invent a second version of that fact. This is how Nova keeps pressure, failure, progress, and truth from being blended into a comforting but inaccurate status.

Nova records actions and outcomes in ledgers and runtime evidence. It runs broad regression testing across its behavior, integrations, tools, memory, autonomy, interfaces, and domain layers. It can also generate focused test sessions from repeated weak signals. This is part of Nova's subconscious system, which looks for patterns that may be easy to dismiss one at a time but meaningful when they keep returning.

When those patterns become strong enough, Nova can bring them into visible work for review and resolution. Its Kidney system manages stale generated material, archives what should be preserved, and cleans what no longer belongs. Its guard watches the running core and can recover it when the process or heartbeat fails. SOCK studies the machine Nova is running on and helps match AI models to the available hardware. Each of these systems has a different job, but they contribute to the same larger ability: Nova can observe itself, respond to what it finds, and retain evidence of what happened.

Honesty does not mean Nova must stop whenever something is imperfect. It means Nova should know the difference between a real blocker, ordinary pressure, unfinished work, and a healthy result. That distinction allows autonomy to keep moving without hiding problems.

## Growth Without Losing Nova

Nova is designed to take in new abilities without forcing every new idea into its core. A new tool, source of information, interface, testing layer, or field of work can be connected through existing contracts. Nova can then discover what the new layer provides, decide how it may be used, test its behavior, watch its health, and include its evidence in the wider system.

The data connector work inside Nova demonstrates this direction. data connector is a standard used by education systems to exchange information. Nova has a reusable data connector core, connection handling, discovery, resource reading, change tracking, district boundaries, diagnostics, and a district-specific data lane. The important point is larger than education: a whole field of work can enter Nova as a connected layer while Nova continues to own the surrounding memory, tools, evidence, testing, and autonomy.

The same principle applies when Nova improves itself. It can inspect areas of code that are becoming too heavy, turn that pressure into organized work, use tools to make bounded changes, run validation, and preserve release evidence. It can preview and review patches, keep snapshots, roll back changes, and record what was promoted. These are working paths for growth, not a promise that every change will be correct. Nova's strength comes from making the work inspectable and making the result answer to evidence.

Growth also includes learning how to remain understandable. Nova tracks where important responsibilities live and checks whether new layers are actually connected from beginning to end. Structural wiring inventories prove declared routes exist; semantic live-closure checks prove known feedback loops can diagnose pressure, produce executable work, and close with valid evidence. This helps prevent a new capability from becoming an isolated feature that looks complete but never reaches the rest of the system. It also helps keep central files from absorbing every responsibility as Nova expands.

## What Mission Means

Nova already has autonomy. Mission gives that autonomy direction.

A mission tells Nova what matters most, what progress means, and which unresolved conditions deserve attention. It gives the system a shared purpose that can guide conversation, planning, tools, ongoing work, testing, maintenance, and growth. Mission does not replace those systems or create a second control plane above them. It receives their truth and helps Nova understand the meaning of that truth in relation to its purpose.

This matters because a capable system can still spend its effort in the wrong place. Nova may be able to find problems, create work, use tools, and improve code, but a mission helps it judge whether that work strengthens the purpose it is meant to serve. It turns capability into direction without reducing Nova to one fixed script.

Nova's purpose can become more specific as the work becomes more specific. The system does not need to be rebuilt around each new goal. Its existing autonomy can learn the domain, connect the needed layers, organize the work, and grow deeper into the mission while preserving the evidence and self-knowledge that keep Nova honest.

## Nova Today

Nova runs locally on Windows and can be used through its Control Room, Leah interface, command line, and voice paths. It has working systems for conversation, memory, planning, tools, web research, vision, ongoing work, background maintenance, testing, recovery, patching, release verification, operator notices, data pipelines, and self-observation.

Nova is still growing because growth is one of its jobs. That does not make its autonomy hypothetical. The runtime operates, maintenance cycles run, work persists, tools produce evidence, tests exercise the system, failures remain visible, and new layers connect to the whole. Nova's current work on its own structure is the system using its autonomy where it is needed most.

The goal is not to make Nova appear perfect. The goal is to build an autonomous system that can know what it is doing, know why it is doing it, know what happened, and keep developing without losing the truth along the way.

## Start Nova

From PowerShell in the Nova directory:

    .\nova.cmd install
    .\nova.cmd doctor
    .\nova.cmd guard
    .\nova.cmd webui-start --host 127.0.0.1 --port 8080

Open the Control Room at http://127.0.0.1:8080/control or Leah at http://127.0.0.1:8080/leah.
