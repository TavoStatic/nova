How it works

A cycle every 5 minutes — whether or not you're there

Each maintenance cycle reads signals from the runtime, converts them into trackable problems, decides what to work on next, and executes one step. The result becomes evidence for the next cycle.

Step 1
Read signals
Errors, health checks, calendar deadlines, regression results
Step 2
Score and track
Signals become branches in the task tracker, ranked by pressure
Step 3
Decide
The orchestrator picks the highest-pressure branch and the right tool
Step 4
Execute and record
Tool runs, result is recorded as evidence, next cycle continues
What's inside

Each component has one job

Nothing is hidden. Every part of Nova is inspectable from the operator control room.

Process management

The process keeper

Starts the runtime, watches it, restarts it on failure with exponential backoff, and triggers the maintenance cycle every 5 minutes. Enforces a single-instance lock so only one keeper runs at a time.

Work tracking

The task tracker

A SQLite database of open problems organized into branches and steps. Each step is a tool call. The orchestrator advances branches one step at a time and records the result as evidence.

Autonomous decisions

The decision engine

Scores each work category by pressure and picks the next action. Respects confidence thresholds and policy allow-lists. Can defer, block, or proceed based on what the runtime evidence shows.

Storage hygiene

The storage keeper

Scans every cycle for stale patch previews, outdated snapshots, bloated temp directories, and low-quality generated test files. Archives or deletes them based on age, size, and quality scores.

Calendar awareness

Deadline tracking

Reads your calendar (ICS files) every 15 minutes, scores upcoming events by deadline pressure, and routes anything above the threshold into the task tracker as a branch to work through.

Test generation

The background simulator

Runs unattended to generate test scenarios, simulate them, and produce candidates for review and promotion into the live system. Runs as a standalone batch job.

Operator communication

The notice board

Where Nova writes things it wants the operator to know about — without waiting for a chat turn. Notices move through statuses: new, seen, answered, resolved. Visible in the control room.

Patch management

The patch system

Stages patches as previews, snapshots the current state before applying, runs a behavioral check afterward, and rolls back automatically if the check fails.

Get running

Quick start

Requires Windows, Python 3.11+, and Ollama running locally with the models pulled.

# Clone and set up git clone https://github.com/TavoStatic/nova.git cd nova .\nova.cmd install .\nova.cmd doctor # Start the runtime and web UI .\nova.cmd run .\nova.cmd webui-start --host 127.0.0.1 --port 8080 # Operator control room → http://127.0.0.1:8080/control
